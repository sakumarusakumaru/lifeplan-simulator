# ライフプランシミュレーター ver4 検証用資料

ほかのAI・専門家に計算の妥当性を検証してもらうための資料です。作成日 2026年10月27日。

- サイト: https://lifeplan-simulator-jp.vercel.app （計算はすべてブラウザ内のJavaScriptで実行。サーバーにデータは送らない）
- 制度の前提: 2026年10月時点の日本の制度（令和8年度）
- 同梱ファイル
  - `lifeplan_検証用_YYYY-MM-DD.json` … 入力データ（名前・連絡先・メッセージを除いたもの）。サイトのメニュー「検証用に保存（個人情報を除く）」で作成
  - `2026_1027_ライフプラン計算エンジン_ver1.zip` … 計算プログラム一式（TypeScript）。画面とは独立した純粋な計算コード
- 運営者はFP・税理士等の有資格者ではありません。概算ツールです

## 1. いちばん確認してほしいこと（前回のフィードバックへの回答）

### 1-1. 「NISAを最後まで残すと3,440万円多い」の根拠

比較の定義は次のとおりです。

| 項目 | 内容 |
|---|---|
| 比べる2本 | 「おすすめ順」と「NISAを先に使う順（NISA→特定口座→金→暗号資産）」。それ以外の入力（利回り・積立・支出・税制）はまったく同じ |
| 比べる値 | 最終年（入力の最終年齢、通常100歳）の「税引き後の純資産」 |
| 税引き後の純資産 | 純資産 − その年末に課税口座（特定口座・金・暗号資産）を全部売ったらかかる税金（含み益 × 税率） |
| 純資産 | 現金 + NISA + 特定口座 + 暗号資産 + 金 + DC − 住宅ローン残高 − 不動産ローン残高 − その他ローン残高。自宅・投資不動産の評価額は含めない |

画面には、差の内訳を次の3つに分けて表示するように直しました（2026-10-27）。

| 内訳 | 計算方法 |
|---|---|
| ① 途中で売ったときに払う税金の差 | 各年の売却時の税金（含み益 × 税率）の合計の差。名目額の単純合計で、運用で増えた分は含まない |
| ② 最後に残る含み益にかかる税金の差 | 最終年の「全部売ったらかかる税金」の差 |
| ③ 運用の差 | 全体の差 − ① − ②。税金を払う時期の違い（先に払った税金はその後運用できない＝課税の繰り延べ効果）、口座ごとの想定利回りの違い、NISA枠の使い直し（売った簿価分の枠が翌年に復活し、積立中ならそこへ再び積み立てられる）を含む |

参考（初期値のサンプルで利回りをそろえた場合）: おすすめ順の方が税引き後で116万円多い。内訳は ① +121万円、② +388万円、③ −393万円。③がマイナスなのは、NISAを先に使うと特定口座の売却（と税金）が後ろにずれ、その間に払っていない税金の分も運用されるため（課税の繰り延べ効果）。

注意点: NISAと特定口座に違う想定利回りを入れている場合、③の大部分はその利回りの差です。 たとえばNISAに株（6%）、特定口座に投信（4%）を入れていると、NISAを長く残すほど有利な結果になります。画面ではこの場合に注意を表示しています。純粋に「口座による税の差」だけを見たい場合は、利回りをそろえて比較してください。

### 1-2. 相続時の取得価額（課税口座とNISAの区別）

画面の説明に誤解を招く表現があったため修正しました。現在の扱いは次のとおりです。

| 口座 | 相続時の取得価額 | シミュレーターの扱い |
|---|---|---|
| 特定口座・一般口座 | 亡くなった人の取得価額を引き継ぐ | 含み益の税（上の②）は相続後も残る、として税引き後に反映 |
| NISA口座 | 相続人の特定口座等へ、相続開始日の時価で移管（それまでの値上がり益に所得税はかからない） | もともと含み益の税をゼロとして扱っているため、計算結果は変わらない。説明文のみ修正 |

どちらも相続税の課税対象です。相続税の取得費加算の特例（相続税の一部を取得費に加算できる、申告期限から3年以内の売却）は入れていません。

## 2. 取り崩しの仕組み

毎年の計算の流れ（`simulate.ts`）。

1. その年の収入・税・社会保険・支出・積立を計算し、年間収支を現金に足す
2. 現金に預金金利をつける（利息は20.315%を引いた後）
3. 積立分を各口座に入れ、1年分運用する（積立は年初に入れて1年分の利回りがつく単純化）
4. 現金が「現金保有下限額」を下回ったら、下回った分だけ運用資産を売って現金に戻す

売る順番:

| 設定 | 順番 |
|---|---|
| おすすめ | 毎年、特定口座・金・暗号資産を「1円売るのにかかる税金」＝（含み益の割合 × 税率）が小さい順に並べて売る。NISAは最後 |
| 自分で決める | 指定した順 |

売る金額は「必要な手取り」から逆算します。

- 含み益の割合 g = 1 − 取得額 ÷ 評価額
- 1円売ったときの手取り = 1 − g × 税率
- 売却額 = 必要な手取り ÷（1 − g × 税率）。その資産で足りなければ全部売って次へ
- 売った割合だけ取得額（簿価）も減らす（平均取得価額で按分）

取り崩しの対象外:

- iDeCo・企業型DC … 取り崩さず、受取開始年齢に一時金（退職所得）または年金（公的年金等）で受け取る
- 自宅・不動産 … 売却しない前提
- 退職金 … 勤務先ごとに一時金／年金／一部年金を選択（4章）

既知の限界: 順番は税金だけで決めており、資産配分（株式比率など）や相場の状況（暴落時に売らない等）は考慮していません。現金保有下限額は利用者の入力値（初期値200万円）で、生活費の何か月分かを画面に表示しています。

## 3. 資産・口座ごとの課税の扱い

| 資産 | 運用中 | 売却時 | 補足 |
|---|---|---|---|
| 現金・預金 | 利息に20.315% | ― | 初期の金利は年0.2% |
| NISA | 非課税 | 非課税 | 年間枠（つみたて120万・成長240万）、生涯1,800万（簿価）・うち成長1,200万をチェック。超過分は特定口座へ（切替可）。売却した簿価分は翌年に枠が復活。旧NISA（2023年まで）の分は生涯枠に数えない |
| 特定口座 | 課税なし（分配金・配当の毎年課税は入れていない） | 含み益 × 20.315% | 損益通算・繰越控除は入れていない |
| 金 | 課税なし | 含み益 × 20.315% | 金ETF等を想定。現物の金（総合課税の譲渡所得、特別控除50万円、5年超保有は1/2）は入れていない |
| 暗号資産 | 課税なし | 2027年まで: 含み益 × 利用者が入力した税率（初期値30%、雑所得の総合課税の目安）／2028年以降: 含み益 × 20.315% | 2028年以降の分離課税は、2026年度税制改正（金商法改正の施行が前提、早くて2028年）を仮定。損失の繰越は入れていない |
| iDeCo・企業型DC | 非課税。本人掛金は全額所得控除 | 一時金: 退職所得（退職金と同じ控除・1/2課税、受取間隔による控除の重複調整あり）／年金: 公的年金等控除で他の年金と合算 | 掛金上限は区分と年で判定（2026年12月掛金分から引上げ） |
| 退職金 | ― | 一時金: 退職所得／年金: 公的年金等 | 4章 |

## 4. 退職金の受け取り方

- 一時金: 退職所得控除（勤続20年まで40万円×年数、20年超は800万円＋70万円×(年数−20)）。（退職金 − 控除）÷ 2 に所得税・復興税・住民税10%
- 年金: 元本を給付利率で運用しながら受取年数で取り崩す年額（年金現価の逆算）。毎年、公的年金等として他の年金と合算して課税。国民健康保険・介護保険の保険料も所得に応じて増える
- 一部年金: 指定割合を一時金、残りを年金
- 画面では3通りについて「受取総額 − 税・社保 ＝ 手取り」を表示。「税・社保」は、その退職金がない場合との一生涯の税・社会保険料の差

## 5. 税・社会保険（詳細モード）

- 所得税: 速算表、復興特別所得税2.1%（2037年まで）
- 基礎控除: 2026・2027年分は合計所得489万円以下で104万円（本則62万＋特例42万）、2028年分以後は本則62万円。住民税は43万円
- 給与所得控除の最低保障: 2026・2027年分74万円、2028年分以後69万円
- 配偶者控除・配偶者特別控除、扶養控除（16〜18歳38万、19〜22歳63万）
- 社会保険（2026年度、本人負担）: 厚生年金9.15%、協会けんぽ4.95%（全国平均9.9%の折半）、介護0.81%（40〜64歳）、子ども・子育て支援金0.115%、雇用保険0.5%。厚生年金の標準報酬月額上限は年ごとに段階引上げ（2027年9月68万〜2029年9月75万）
- 退職後: 国民年金（60歳未満）、国民健康保険（全国平均的な料率で概算）、75歳以上は後期高齢者医療、65歳以上は介護保険第1号（2段階の概算）
- 住民税が前年所得にかかるタイムラグは入れていない

## 6. 公的年金・遺族年金・相続税

- 老齢基礎年金 満額 847,300円（令和8年度）、加給年金 423,700円、繰上げ0.4%/月・繰下げ0.7%/月
- 遺族基礎年金 847,300円＋子の加算（1・2人目243,800円、3人目以降81,300円）、遺族厚生年金は報酬比例の3/4（在職中の死亡は300月みなし）、中高齢寡婦加算635,500円
- 相続税: 基礎控除 3,000万＋600万×法定相続人、法定相続分で按分して速算表、配偶者の税額軽減（配偶者が法定相続分を相続した前提）。生命保険金の非課税枠500万×法定相続人。小規模宅地等の特例・路線価評価・生前贈与の加算・二次相続は入れていない

## 7. 外的環境（比較タブ）

- 大暴落: N年に1度、その年の株式・投信・DCが42%下落（暗号資産60%）、その後4年かけて暴落がなかった場合の水準へ回復
- 金利上昇: 住宅ローン・不動産ローン金利に上乗せ（変動金利を想定、今から上がる）、預金金利は半分だけ上がる
- 物価上昇: 物価上昇率を置き換え。給与は据え置き、年金は物価上昇の7割だけ追いつく
- 運用の低迷: NISA・特定口座・DCの想定利回りを下げる
- 年金の目減り: 年金額の改定率を下げる

## 8. 検証してほしい観点（チェックリスト）

1. 「おすすめ順」の基準（含み益の割合 × 税率が小さい順、NISA最後）は、税引き後の最終資産を増やす方向として妥当か。反例となる条件はあるか
2. 比較の指標（最終年の税引き後純資産）は妥当か。途中の年の資金繰り（資金ショート）の評価と矛盾しないか
3. 差の内訳（①売却時の税、②最終の含み益の税、③運用の差）の分け方は妥当か
4. 資産ごとの課税（3章）の単純化で、結論が変わりうるものはどれか（特に金・暗号資産、分配金の毎年課税の省略）
5. 相続時の取得価額の扱い（1-2）は正しいか
6. 退職金の一時金／年金の比較（4章）の考え方は妥当か

## 9. 計算プログラムの構成（zip の中身）

| ファイル | 役割 |
|---|---|
| `simulate.ts` | 年ごとのシミュレーション本体。取り崩し・売却税・含み益の税（latentTax）・退職金の受け取り方・死亡シナリオ |
| `tax.ts` | 所得税・住民税・社会保険料・退職所得 |
| `rules.ts` | NISA枠・iDeCo上限・児童手当 |
| `pension.ts` / `survivor.ts` | 老齢年金・遺族年金 |
| `inheritance.ts` | 相続税の目安 |
| `drawOrder.ts` | 取り崩し順（自分で決める場合） |
| `environment.ts` | 外的環境（暴落と回復・金利・物価など） |
| `montecarlo.ts` | 運用の振れ幅（1,000回） |
| `realValue.ts` | 今の価値への換算 |
| `types.ts` / `defaults.ts` | 入力項目の定義と初期値 |
| `DrawOrderEditor.tsx` | 取り崩し順の比較（おすすめ順とNISA先の比較・差の内訳）を計算・表示する画面部品 |

入力JSONの項目の意味は `types.ts` の `PlanInput` にコメント付きで定義しています。JSONの `plan` をそのまま `simulate(plan)` に渡すと、画面（金額の表示が「名目」のとき）と同じ計算結果になります。同梱の `verify.ts` で、比較と差の内訳・年ごとの表を出力できます（README参照）。
